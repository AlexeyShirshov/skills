# План реализации «линзы» PDCA

**Основание:** `2026-10-24-pdca-lensing-design.md` (490 строк, «На согласовании»).
**Разрешения пользователя:** реализация спеки; правка тестов; docs и диаграммы.
**Запрещено:** коммиты, push, vendor, snapshot, живой хост, CI.

## Целевая раскладка

```text
skills/pdca/                     # единственный публичный вход + базовый цикл
  SKILL.md                       # ядро: вход, формы, режимы, линза, гейты, статус
  references/plan.md             # PLAN: поля, команды, манифест, пороги, исключения
  references/check.md            # CHECK: свидетельства, несущие утверждения, вето
  references/act.md              # ACT: закрытие, шаблон статуса, следующая сессия
  assets/, scripts/, tests/
skills/pdca-coder/               # оверлей: только отличия кодовой работы
skills/pdca-dotnet/              # оверлей: наследует coder, добавляет .NET
skills/pdca-incremental/         # incremental-кампания (форма, не оверлей)
skills/pdca-collection/          # пакет независимых целей (форма, не оверлей)
skills/pdca-entry/               # удаляется: правила входят в PLAN базового pdca
```

## Этапы

1. **База.** Переписать `skills/pdca/SKILL.md` в ядро (< 50 KiB, ориентир ~35 KiB);
   вынести `references/{plan,check,act}.md`; внести вход/классификацию, линзу и границу шага,
   владельца кампании, несущие утверждения и вето, provisional-пороги, оверлеи.
2. **Роли.** Обновить `assets/opencode-agents/*.md`: planner (форма + claims + граница шага),
   orchestrator (campaign-control / cycle-control), check (claims/veto), остальные — точечно.
   Один и тот же runner во всех пакетах.
3. **Оверлеи.** `pdca-coder` → оверлей (наследование базы, кодовые отличия);
   `pdca-dotnet` → оверлей над coder. Никаких полных копий цикла.
4. **Формы.** `pdca-incremental` и `pdca-collection` приводятся к новым семантикам
   (линза, граница шага, владелец кампании, вето, provisional-пороги, размер контракта).
5. **Вход.** Удалить `skills/pdca-entry`; публичный вход — `pdca`; обновить диаграммы.
6. **Документация.** `docs/pdca.md`, `docs/ru/pdca.md`, `README.md`, `AGENTS.md` источника,
   `docs/install.md` — под новый вход и формы.
7. **Тесты.** Переписать suite под новый контракт: единый вход, оверлеи, лимит размера,
   учёт вызовов planner'а, вето, перенос знания; скриптовые гейты и permission-проверки
   сохранить. Прогнать все suite, зафиксировать результат.

## Проверки

- `wc -c` каждого `SKILL.md` ≤ 50 KiB (цель ≤ 35 KiB), строк ≤ 2000.
- Ссылки `../<skill>/SKILL.md §Anchor` разрешаются.
- Никаких `model:` в ролях; тиры только `# tier:`.
- `git status` — изменены/удалены только файлы PDCA-семейства, docs и тесты; `.opencode/`,
  `experiments/`, спека не тронуты.
