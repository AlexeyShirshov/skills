# Запустите первый цикл PDCA

[English](../../guide/first-cycle.md)

Если вы впервые используете PDCA, начните с задачи на чтение локального Git-репозитория. Вы одобрите контракт результата и сверите ответ с файлами, не меняя продукт.

## Что понадобится

Подготовьте репозиторий с корневым `README.md`, в котором есть хотя бы одна ссылка на локальный файл, среду с поддержкой ролей PDCA и разрешение на запись состояния в `.pdca/`.

## Запуск и проверка результата

1. Настройте свою среду по [инструкции установки](../install.md). Убедитесь, что нужные роли доступны и скиллы загружаются: одного присутствия скилла в списке недостаточно.
2. В сессии этого репозитория отправьте запрос:

   ```text
   Запусти pdca в обычном режиме. Перечисли без повторов существующие
   файлы, на которые ссылается корневой README.md. Дай пути от корня
   репозитория в алфавитном порядке. Не меняй файлы продукта и не коммить.
   ```

3. Откройте сохранённый PLAN по ссылке агента. Убедитесь, что он обещает запрошенный список, а не общий аудит ссылок. Если план подменяет задачу, не одобряйте его.
4. Одобрите именно этот план. Вопрос об остановке по оценке усилий — отдельное решение: он не заменяет одобрение плана, а одобрение не вводит лимит.
5. После ACT откройте указанный статус-файл. Убедитесь, что CHECK принял результат и указал на доказательства. Сверьте один путь из ответа со ссылкой в README и файлом на диске.

Если PLAN установил результат сразу, ищите вывод и его обоснование в ACT: независимый CHECK не запускался. Если запуск заблокирован, устраните проблему с конкретной ролью или скиллом по инструкции агента, а не просите его пропустить проверку.
